# Layout draft

## Idea
**Purpose:** temporary page to review the layout of the support console before any data layer is written. Static data, no requests, no streams.

The console is a typical busy internal app: a top bar with global search and notifications, a customer list, the selected customer with tabs, a side rail with shipments and activity, and an order drawer. The page uses the wide layout, so this description sits under the demo instead of in a side pane.

## Try it
- Pick another customer, switch the tabs, click an order row to open the drawer.
- Tickets tab: open SO-58213 from T-9921 ("I forgot to add a belt"), press **Edit items**, add the belt from the catalog, see the price difference. SO-57940 from T-9874 has shipped, so it offers a return instead.
- Click a ticket to read the conversation and reply (agents answer tickets, they don't open them).
- Close the customer (✕) to see the "nothing selected" state.
- Log out to see the signed-out screen.
- Resize the window: three columns from about 1150px of demo width, two below, one on phones.
